## Project Overview
`habit-api` is a small REST service for a habit tracker. It is an educational assignment: design an OpenAPI 3.0 spec and generate a service skeleton from it. No real persistence, no real auth — in-memory stubs behind generated interfaces.

## Architecture
Stateless Spring Boot HTTP service generated by `openapi-generator-cli` from `api.yaml` (OpenAPI 3.0, generator `spring`). Layered: controllers (generated) → service (hand-written) → in-memory store. No database. Auth is a static Bearer token check for demonstration only.

## Project Layout
Repository root holds the spec; generated code lives under `service/`.

- `api.yaml` — OpenAPI 3.0 spec. Source of truth. Every endpoint change starts here.
- `service/` — output of `openapi-generator-cli generate -i api.yaml -g spring -o service`. Do not hand-edit generated controllers, models, or interfaces; they will be overwritten on the next generate.
- `service/src/main/java/**/api/` — generated controller interfaces.
- `service/src/main/java/**/model/` — generated DTOs (`Habit`, `HabitInput`, `HabitListResponse`, `Error`).
- `service/src/main/java/**/service/` — hand-written business logic and in-memory store (`HabitService`, `HabitStore`).
- `README.md` — how the spec and the generated service were produced (hand-written vs agent, which prompts, what was fixed manually).
- `service/pom.xml` — Maven build for the generated service.

**Rule:** endpoints and schemas are changed in `api.yaml` first, then regenerated. Hand-written code lives only in the `service` package (and equivalents), never in generated packages.

## Tech Stack
- OpenAPI 3.0 (`api.yaml`), validated in editor.swagger.io.
- `openapi-generator-cli` (`@openapitools/openapi-generator-cli`, run via `npx` if not installed globally).
- Generator: `spring` (Spring Boot, Java 17+, Maven).
- `service/` builds and runs with Maven: `mvn -q package`, `mvn spring-boot:run`.

## Commands

| Purpose | Command |
|---|---|
| Validate spec | `npx @openapitools/openapi-generator-cli validate -i api.yaml` |
| Generate service | `npx @openapitools/openapi-generator-cli generate -i api.yaml -g spring -o service` |
| Build service | `cd service && mvn -q package` |
| Run service | `cd service && mvn spring-boot:run` |
| Import into Postman | Postman → Import → OpenAPI → select `api.yaml` |

Notes:
- Run generation from the repository root; `service/` will be overwritten.
- If `service/pom.xml` or generated sources are stale, regenerate rather than patching by hand.
- Docker is out of scope for this assignment.

## Endpoints (target, per `api.yaml`)
- `GET /habits` — list, optional `active` filter.
- `GET /habits/{habitId}` — one habit, 404 if missing.
- `POST /habits` — create from `HabitInput`.
- `PUT /habits/{habitId}` — update, 404 if missing.
- `DELETE /habits/{habitId}` — delete, 404 if missing; 403 if the habit is not owned by the caller.
- All endpoints require Bearer auth: 401 when the token is missing or invalid.

- Errors never pass silently: return the generated `Error` DTO with a meaningful `message`.
- No TODO placeholders in deliverable code. If something is a stub (auth, storage), say so in `README.md`.
