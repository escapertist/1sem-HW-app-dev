# Spec Delta

## Purpose

Ограничение доступа к API привычек: каждый запрос к `/habits` должен предъявить Bearer-токен, а
операции над привычкой доступны только её владельцу. Заглушка для демонстрации: набор токенов
статический, без выдачи, обновления и отзыва.

## ADDED Requirements

### Requirement: Аутентификация по Bearer-токену

Все эндпоинты `/habits` MUST требовать заголовок `Authorization: Bearer <token>`. Если заголовок
отсутствует, не соответствует схеме или токен неизвестен, сервис MUST отвечать 401 с телом
`Error` и MUST NOT выполнять запрошенную операцию.

#### Scenario: Заголовок отсутствует

- **WHEN** клиент вызывает `GET /habits` без заголовка `Authorization`
- **THEN** сервис отвечает 401 и `Error` с непустым `message`

#### Scenario: Токен неизвестен

- **WHEN** клиент передаёт `Authorization: Bearer unknown-token`
- **THEN** сервис отвечает 401 и `Error`, данные привычек не возвращаются

#### Scenario: Схема отличается от Bearer

- **WHEN** клиент передаёт `Authorization: Basic ...`
- **THEN** сервис отвечает 401 и `Error`

#### Scenario: Действительный токен

- **WHEN** клиент передаёт `Authorization: Bearer` с известным сервису токеном
- **THEN** запрос обрабатывается обычным образом и сервис не отвечает 401

### Requirement: Изоляция привычек по владельцу

Сервис SHALL связывать каждую привычку с владельцем, определяемым предъявленным токеном.
`GET /habits` MUST возвращать только привычки вызывающего. Обращение к привычке другого
владельца по идентификатору (`GET`, `PUT`, `DELETE /habits/{habitId}`) MUST давать 403 с телом
`Error`, а не 404 и не данные привычки.

#### Scenario: Список ограничен владельцем

- **WHEN** вызывающий запрашивает `GET /habits`, а в хранилище есть привычки двух владельцев
- **THEN** в ответе только привычки вызывающего

#### Scenario: Чтение чужой привычки

- **WHEN** вызывающий читает по идентификатору привычку другого владельца
- **THEN** сервис отвечает 403 и `Error`, тело привычки не возвращается

#### Scenario: Обновление чужой привычки

- **WHEN** вызывающий отправляет `PUT /habits/{habitId}` для привычки другого владельца
- **THEN** сервис отвечает 403 и `Error`, данные привычки не изменяются

#### Scenario: Удаление чужой привычки

- **WHEN** вызывающий отправляет `DELETE /habits/{habitId}` для привычки другого владельца
- **THEN** сервис отвечает 403 и `Error`, привычка остаётся в хранилище
